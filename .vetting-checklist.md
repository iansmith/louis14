## CountersAttachmentContext family

1. **Plan §"Root cause: there is no counter tree"** (line 56–66) —
   `third_party/blink/renderer/core/css/counters_attachment_context.{h,cc}`
   - "added 2024"
   - Owns `CounterInheritanceTable` (name → stack of `CounterEntry{layout_object, value}`)
   - Threaded through single pre-order traversal with `EnterObject` / `LeaveObject`
   - `MaybeCreateListItemCounter`, `ElementGeneratesListItemCounter` create implicit `list-item` for `ol/ul/li/menu/dir`
   - Seeded from `HTMLOListElement::InitialCounter()` (`start`/`reversed`) and `ListItemOrdinal` (`li[value]`)

2. **Phase 1 — counters_attachment_context.h** (lines 137–145):
   - `CounterEntry{Member<const LayoutObject> layout_object; int value;}`
   - `CounterStack = HeapVector<Member<CounterEntry>>`
   - `CounterInheritanceTable = HashMap<AtomicString, CounterStack>`
   - `enum Type {kIncrementType, kResetType, kSetType}`
   - Methods: `EnterObject`, `LeaveObject`, `GetCounterValues`, `ProcessCounter`,
     `CreateCounter`, `UpdateCounterValue`, `RemoveStaleCounters`,
     `RemoveCounterIfAncestorExists`, `ShallowClone`/`DeepClone`.

3. **Phase 1 — counters_attachment_context.cc** (lines 146–166):
   - `ProcessCounter` → `RemoveStaleCounters` first, then `CreateCounter` (reset) or `UpdateCounterValue`
   - `CreateCounter` (reset) pushes new `CounterEntry` unconditionally, removes innermost counter if its originating element *is* `layout_object` or a *previous sibling*
   - `UpdateCounterValue` mutates topmost entry; empty stack or containment-boundary → `CreateCounter` w/ implicit value (0)
   - `RemoveStaleCounters` pops entries whose origin's `LayoutParentElement` is NOT ancestor of element being entered (`IsAncestorOf`)
   - `RemoveCounterIfAncestorExists` runs in `LeaveObject` for reset counters
   - `GetCounterValues` walks stack in reverse; stops at containment-boundary `nullptr` entries

4. **Phase 2** (lines 221–230):
   - `ProcessCounter` handles `kSetType` like increment except *assigns*
   - Instantiation value for bare `counter-set: n` is 0
   - `display:contents` participates (no box, but `Enter/LeaveObject` runs)
   - `display:none` not in layout tree
   - Counters saturate int32 — uses `base::ClampedNumeric`

5. **Phase 3** (lines 260–272):
   - `ElementGeneratesListItemCounter(Element)` returns true for `ol/ul/li/menu/dir` (and `display:list-item`)
   - `MaybeCreateListItemCounter(Element)` called from `EnterObject`
   - Seeds implicit `list-item` from `ListItemOrdinal` (`li[value]`) and `HTMLOListElement::InitialCounter()`
   - `<li>` no explicit `value` → implicit `counter-increment: list-item 1`
   - Explicit `value` → implicit `counter-set: list-item N`

6. **Phase 3 — list_marker.cc OrdinalValue / ListItemForMarker** (line 270):
   - Reads `list-item` counter value out of attachment context
   - Marker text = `counter(list-item)` formatted by item's CounterStyle

7. **Phase 4 — CalculateInitialValueForReversed** (lines 302–315):
   - Implements <https://drafts.csswg.org/css-lists/#instantiating-counters>
   - Traverse DOM forward within parent scope, accumulating negation of every `counter-increment` and `counter-set`
   - Break at sibling `counter-reset` of same counter
   - Plain `<li>` under `<ol reversed>` increments `list-item` by −1
   - `<ol reversed>` resets `list-item` with `reversed(list-item)`; initial value via CalculateInitialValueForReversed, offset by `start`
   - `CSSListCounterAccountingEnabled` gates spec-correct path
